# docs/learnings/ — Schema

The learning history written by the `learn` skill. `.agents/scripts/learnings.py` is the only writer of `entries/` and `INDEX.md`; `check` enforces this file at pre-commit.

## Layout

- `entries/<slug>.md` — one file per learning. The slug is lowercase words joined by `-`.
- `INDEX.md` — generated by `learnings.py index`, never edited by hand: one row per learning, sorted by slug.

## Entry format

```markdown
---
category: asset_interpretation_gaps
failure_mode: skill_unexpected_behavior
asset_path: .agents/skills/git-commit/SKILL.md
asset_section: Fresh worktree
symptom: git commit blocked in a fresh worktree because direnv was not allowed
status: fixed
fixed_by: learning/2026-10-02-zonier-es-postgres-search-2
fix_target: .agents/skills/git-commit/SKILL.md#Fresh worktree
fix_why: document direnv allow
fixed_at: 2026-10-05
fix_pr: https://github.com/acme/app/pull/1
backfilled: true
---

## Occurrences

- spec=2026-10-02-zonier-es-postgres-search increment=2 date=2026-10-05 evidence="exit_code 1 on git commit"
```

- Front matter is flat `key: value`, one line per key, no YAML library.
- Required: `category`, `failure_mode`, `asset_path`, `asset_section`, `symptom`, `status`. A finding with no asset uses `none` for `asset_path` and `asset_section`.
- `status` is `detected` or `fixed`. `fixed` also requires `fixed_by` (branch), `fix_target` (`file#section`), `fix_why`, `fixed_at` (`YYYY-MM-DD`). `fix_pr` is set once the learning PR exists; `backfilled: true` marks an entry recovered from a past PR.
- `## Occurrences` is append-only: one line per occurrence, `key=value` pairs, a value with spaces is a JSON string. Keys: `spec`, `increment`, `date` (required), `evidence`, `discarded_by` (the filter that removed the finding), `related_to` and `related_reason` (the finding was `related` to another learning).
- One occurrence per `(slug, spec, increment)`: recording it again updates it.

## Matching

The match key is `category + failure_mode + asset_path + asset_section`, unique across entries.

| `match` answers     | When                                                                                                                                             |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| `new`               | no entry has the key and none shares the `asset_path`                                                                                            |
| `match: <slug>`     | an entry has the same key: record an occurrence on it                                                                                            |
| `related: <slug,…>` | entries share the `asset_path` but differ by section, mode or category: never a merge, record a new entry with `related_to` and `related_reason` |

## Index status

`detected`, `fixed`, or `recurred` (a `fixed` entry with an occurrence dated after `fixed_at`; an occurrence on that day is not a recurrence).

## Failure modes

`failure_mode` belongs to its category (closed vocabulary, held by `FAILURE_MODES` in `learnings.py`):

| `category`                  | `failure_mode`                                                                                                       |
| --------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `asset_interpretation_gaps` | `agents_md_not_followed`, `skill_unexpected_behavior`, `standard_not_followed`, `workflow_not_followed`              |
| `bad_expectation`           | `skill_false_trigger`, `skill_missed_trigger`, `agents_md_degrades`, `ontology_degrades`, `spec_corrected_midflight` |
| `time_cost`                 | `task_too_long`, `task_looping`                                                                                      |
| `side_improvement`          | `adr`, `lint_hook`, `observability`, `principle`                                                                     |

## Commands

```bash
python3 .agents/scripts/learnings.py match  --category C --failure-mode M --asset-path P --asset-section S
python3 .agents/scripts/learnings.py record --slug SLUG --category C --failure-mode M --asset-path P --asset-section S --symptom T --spec SPEC --increment N --evidence E [--discarded-by FILTER] [--related-to SLUG --related-reason R]
python3 .agents/scripts/learnings.py record --slug SLUG --fixed-by B --fix-target F#S --fix-why W --fixed-at D
python3 .agents/scripts/learnings.py record --slug SLUG --fix-pr URL
python3 .agents/scripts/learnings.py index
python3 .agents/scripts/learnings.py check
```

All take `--docs-root` (default `docs/learnings`). `record` with only a slug and fix fields or `--fix-pr` amends an existing entry and adds no occurrence.
